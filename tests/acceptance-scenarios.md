# 멀티 에이전트 인수 테스트

## 시나리오 1: 계획서만 요청

입력: `도시 공원의 녹지와 여름철 온도의 관계를 연구계획서로 만들어줘.`

- 팀장이 연구계획서 담당만 실행한다.
- 연구 폴더에 계획서·가정·검수 파일이 생긴다.
- 계획서 요청은 완료로 처리하고 문헌검색은 `범위 밖·미실행`으로 기록한다.

## 시나리오 2: 계획서와 핵심 문헌 요청

입력: `중학생의 스마트폰 사용과 학업성취도를 연구하고 싶어. 계획서를 만들고 관련 핵심 논문도 찾아줘.`

- 연구계획서 담당이 먼저 세 파일을 만든다.
- G1이 16점 이상이고 0점이 없을 때만 문헌검색 담당이 시작한다.
- 문헌검색 담당이 검색전략, 핵심 문헌과 검색 검수 파일을 만든다.
- DOI·URL을 확인하지 못한 문헌은 채택 목록에 넣지 않는다.
- 팀장이 G2와 G3를 확인하고 실제 경로와 한계를 보고한다.

## 시나리오 3: 부실한 계획서 인계 차단

조건: 연구 질문이나 분석 방법이 비어 있거나 검수 점수가 15점이다.

- 팀장이 G1을 `수정 필요`로 판정한다.
- 문헌검색 담당을 실행하지 않는다.
- 연구계획서 담당에게 문제 위치와 수정 조건을 반환한다.
- 세 번의 검수 후에도 미달이면 사용자에게 선택지를 제시한다.

## 공통 실패 조건

- 사용자가 전문 담당에게 직접 명령해야만 작업이 이어짐
- 팀장이 게이트 기록 없이 통과했다고 보고함
- 존재하지 않는 문헌·DOI·연구 결과를 생성함
- 명세 버전이 다른 파일들을 최종본으로 함께 전달함
- API 키, 개인정보 또는 논문 원문을 공개 저장소에 포함함
